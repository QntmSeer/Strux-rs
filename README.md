# strux-rs

[![Language](https://img.shields.io/badge/Language-Rust-orange.svg)]()
[![Python Bindings](https://img.shields.io/badge/Python-PyO3_/_Maturin-blue.svg)]()
[![PyPI Package](https://img.shields.io/badge/PyPI-v0.5.1-blue.svg)](https://pypi.org/project/strux-rs/)
[![CUDA](https://img.shields.io/badge/CUDA-12.x_QCP-76b900.svg)]()
[![License](https://img.shields.io/badge/License-MIT-green.svg)]()

Fast, zero-C-dependency Rust + CUDA engine with Python bindings (`PyO3` / `NumPy`) that bridges **AI protein structure prediction** (AlphaFold 3, Boltz-1/2, Chai-1, AF-Cluster) and **molecular dynamics (MD) ensemble biophysics** (GROMACS `.xtc`, OpenMM/NAMD `.dcd`, PCA, and Markov State Models).

```bash
pip install strux-rs
```

Prebuilt wheels cover Python 3.8+ on Linux x86_64, Windows x64 and macOS arm64. On Linux and Windows they include the CUDA functions (`cuda_pairwise_rmsd`, `cuda_cluster_daura`, `cuda_contact_map_bitmask`, `cuda_contact_frequency`). No CUDA toolkit is needed, only:

* an NVIDIA GPU with compute capability 7.5 or newer (Turing and later: RTX 20xx, T4, A100, L4, H100), and
* an NVIDIA driver that supports CUDA 12.5 or newer, with `libcuda.so` (Linux) or `nvcuda.dll` (Windows) on the library path.

Check with `strux_rs.cuda_is_available()`. Without a usable GPU it returns `False`, the `cuda_*` functions raise `RuntimeError`, and all CPU functions work as normal. macOS wheels are CPU-only.

## Highlights

* **High-Throughput Ingestion & In-Flight Filtering**: Memory-mapped `.xtc`, `.dcd`, `.cif` (AF3/Boltz/RCSB), and `.pdb` readers with zero-copy atom-index and $C_\alpha$ subsetting during decompression (**73.6×** faster than MDAnalysis, **1.4×** faster than MDTraj).
* **De Novo Protein & Therapeutic Design Biophysics**: Target-anchored Pose RMSD & monomer scRMSD (**10,000 complexes in 4.03 ms**, **326×** vs NumPy SVD), interface geometry (buried polars heuristic, polar contacts, salt bridges), 96-point Shrake-Rupley BSA (**1.96 ms** for 2,048 atoms), screened Debye-Hückel $\Delta\Delta G_{\text{pH}}$, ANM normal modes, and developability screening (100k sequences in 270 ms).
* **AI-Accelerated Simulation (AMS)**: AlphaFold lDDT (**201×** faster than NumPy), greedy sequence identity clustering (AF-Cluster style) (**33.8×** faster), Cartesian PCA (**5.1×** faster), and Markov state transition populations at **103.9M frames/s**.
* **CUDA GPU Acceleration**: Pairwise RMSD at **2.05M alignments/s** (**4,348×** over Biopython, **25.3×** over Google JAX), Daura conformational clustering, and dense contact frequency matrices (**19.5×** speedup).

## Quickstart

```python
import strux_rs

# 1. Structure & Trajectory I/O with in-flight CA/atom filtering
coords, plddt = strux_rs.parse_cif_with_plddt("af3_model.cif", ca_only=True)
traj = strux_rs.parse_xtc("md_production.xtc", atom_indices=ca_indices)

# 2. De novo therapeutic binder triage
sc_rmsd, pose_rmsd = strux_rs.batch_pose_and_sc_rmsd(
    ref_target_ca, ref_binder_ca, mob_targets_ca, mob_binders_ca
)
contacts, polar_contacts, salt_bridges, buns, buns_idx = strux_rs.analyze_interface_physics(
    coords[0], atom_names, res_names, chain_ids, res_ids, target_chain="A", binder_chain="B"
)
bsa_total, sasa_tgt, sasa_bnd, sasa_cpx = strux_rs.calculate_bsa(
    target_coords, binder_coords, target_radii=target_vdw_radii, binder_radii=binder_vdw_radii
)

# 3. lDDT (pooled global score, as in AlphaFold / OpenStructure) & GPU pairwise alignment
global_lddt, per_res_lddt = strux_rs.calculate_lddt(coords_a, coords_b)
if strux_rs.cuda_is_available():
    rmsd_matrix = strux_rs.cuda_pairwise_rmsd(traj)
    cluster_labels, centroids = strux_rs.cuda_cluster_daura(traj, cutoff=2.0)
```

## Accuracy

Checked against reference tools on the bundled `trajectory.pdb` (21 frames, 969 heavy atoms, two chains).
The table is generated by `benchmarks/accuracy_report.py`, which also writes `benchmarks/accuracy.json`;
`tests/test_accuracy.py` asserts the same comparisons.

| Quantity | Reference | Max difference |
| :--- | :--- | :--- |
| XTC read, full and atom subset | MDTraj | 1.5e-05 Å |
| DCD read, full and atom subset | MDTraj | 7.6e-06 Å |
| Kabsch RMSD | NumPy SVD (float64) | 9.0e-06 Å |
| Target-anchored pose RMSD | NumPy SVD (float64) | 3.2e-05 Å |
| Binder-only RMSD | NumPy SVD (float64) | 8.8e-07 Å |
| Radius of gyration | MDTraj | 2.5e-05 Å |
| SASA, element radii, 1000 pts | FreeSASA | 0.14% |
| BSA, element radii | FreeSASA | 0.10% |
| BSA, default 1.70 Å radius | FreeSASA, element radii | 2.75% |
| lDDT, global (pooled pairs) | AlphaFold / OpenStructure formula | 2.7e-08 |
| lDDT, per residue | same formula | 2.9e-08 |

Notes:

* **BSA radii.** Without `target_radii` / `binder_radii`, every atom gets a 1.70 Å radius, which overestimates BSA (row above). Pass element van der Waals radii for FreeSASA-comparable values.
* **Interface terms are distance heuristics.** `analyze_interface_physics` counts polar contacts (cross-chain N/O within 3.5 Å, no angle or donor/acceptor check), salt bridges, and buried polar atoms without a nearby N/O partner. This is not Rosetta `BuriedUnsatHbonds`, and it has not been compared against Rosetta.
* **lDDT (changed in 0.5.0).** The global score now pools all scored distance pairs, as in AlphaFold `lddt(per_residue=False)` and OpenStructure. Up to 0.4.x it averaged per-residue scores, which differed by up to 0.03 on this trajectory. Per-residue scores are unchanged. No stereochemistry checks are applied.
* **Not covered here:** the CUDA kernels (no GPU in the test environment; `cuda_is_available()` returning `False` without a GPU is tested), MSA parsing and clustering, PCA, ANM, pH ΔΔG and sequence screening.

## Benchmarks

Benchmarked on Intel Core i9-11950H (16 hardware threads, 62 GB RAM) and NVIDIA RTX A2000 Laptop GPU (4 GB VRAM, 35W TGP).

CUDA timings in Section 1 and Section A below were recorded during 0.4.x development. Starting in 0.5.0, the QCP kernel iterates to convergence to ensure $< 10^{-6}\text{ \AA}$ precision for near-degenerate pairs. Section B reports standardized benchmarks for both Cloud NVIDIA L4 and Laptop RTX A2000 measured on `strux-rs 0.5.1`.

Reproducibility: `scripts/run_gold_standard_benchmark.py` reads `benchmarks/data/2K39.pdb` (download from the RCSB PDB), `benchmarks/data/hmm_output.sto` and `benchmarks/data/bfd_uniclust_hits.a3m`. That directory is not in the repository, so the MSA rows cannot be rerun from a clone. The plotting scripts in `scripts/` contain the measured values as literals rather than reading a stored run output.

## Build from Source

Requires Rust ($\ge 1.75$). For the CUDA build, `build.rs` compiles `src/cuda/kernels/qcp.cu` with `nvcc` if it is on the path; otherwise generate the PTX first with NVRTC (no GPU needed), as CI does:
```bash
git clone https://github.com/QntmSeer/strux-rs.git
cd strux-rs
pip install maturin
# only needed without nvcc:
pip install "cuda-python>=12.9,<13" "nvidia-cuda-nvrtc-cu12==12.5.*" && python compile_ptx.py
maturin develop --release --features cuda
```
